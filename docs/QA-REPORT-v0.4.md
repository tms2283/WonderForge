# WonderForge 2027 · Engineering v0.4 QA and Acceptance Report

**Test date:** November 22, 2026 (US Eastern). **Target:** one shared Raspberry Pi 4B 4 GB running 64-bit Raspberry Pi OS Desktop (Debian Trixie). **Execution environment:** non-Pi Linux x86_64 development container. Hardware-dependent validations below remain open.

## Executed and passed

- **23 Python unittest tests, all passed.** The original seven catalog/http tests, seven OS-integration API tests and nine static deployment contract tests.
- **JavaScript syntax:** `node --check web/app.js` passed.
- **Python syntax:** `python3 -m py_compile server.py tools/*.py` passed.
- **Shell syntax:** `bash -n installer/*.sh scripts/*.sh image/*.sh` passed.
- **Frontend:** `python3 tools/verify_linux_ui.py` passed using headless Chromium and the exact bundled HTML, CSS, JavaScript and image bytes. Actual API requests are mocked in this browser test; they are separately tested with the real Python HTTP service. Both Atlas and Nova states were exercised.
- **Profile enforcement:** real-Unix-identity response prevents the UI's visual picker from impersonating the other account.
- **Shared folder API:** two authors, notebook roundtrip, blueprint coordinate and material validation, cross-site write rejection, Host and Origin policy, and symlink refusal.
- **Allowlisted launch API:** approved installed app detection and launch restrictions. The test mocks the process creation, so it does **not** prove that Luanti or a graphics app launches on actual ARM64.
- **Deployment scripts:** safe dry runs of account provisioner, app installer, offline guard and image script. Refusal conditions for non-Pi hosts and unprivileged/no-graphics cases are covered by source reviews and specific tests.
- **Debian package:** the reproducible `scripts/build-deb.sh` generated byte-identical `.deb` files in two successive builds (matching SHA-256). `dpkg-deb --info` and `--contents` succeeded. After `dpkg-deb -x`, the extracted payload server responded to real HTTP requests for `/` and `/api/session`; the Luanti worldmod existed in the extracted package. The package alone does **not** create users, install suggested apps, or modify networking.
- **Release ZIP:** integrity passes `zipfile.testzip()`; every bundled source file has a SHA-256 manifest entry (see release SHA-256 receipt).

## Real security work versus non-guarantees

- Installed system uses Unix users `atlas` and `nova`, private home directories (`0700`), and an explicitly shareable `wonderforge`-group folder (`2770`). The installer is an opt-in root action **only after** a physical hardware / architecture / OS guard.
- Per-user localhost HTTP service, bounded API and fixed app-launch allowlist materially reduce attack surface. It has not undergone an external professional penetration test, and native browser security remains relevant.
- Optional nftables UID-output guard is off by default. If enabled, it blocks child-owned external network sockets, including LAN gaming; it is **not** a comprehensive child-safety appliance, DNS category filter, or time-limit product.
- Parent Desk UI is guidance, **not** proof of privileged parental controls.
- ORBIT remains explicitly scripted, not a large offline generative AI.

## Not executed / release blockers

1. **Real Raspberry Pi installation:** no physical Pi 4B was available to execute account creation, user service, Chromium kiosk window, storage permissions and shared copying after reboot.
2. **Real Luanti world:** 7-island VoxelManip map generator and 6-region quest mod is packaged but not tested in a running Luanti 5.10 game. No Luanti binary nor Lua interpreter is installed in this development host.
3. **Custom bootable `.img`:** image builder requires a suitable ARM64 host with mount capabilities. A lintable YAML + first-boot recipe is delivered; there is **no successfully built, flashed, boot-tested, ready-to-use custom image**.
4. **Actual parental enforcement:** policy requires adult review, optional explicit installation, and real tests with both non-admin accounts; do not enable before backup/recovery preparation.
5. **Performance metrics:** idle RAM, Chromium responsiveness, 3D FPS, audio latency, temperature/throttle and reboot reliability on 4 GB Pi remain **unmeasured**.
6. **Full accessibility review:** screenreader, contrast, low-vision zoom, keyboard-only and controller support require deeper tests with target users.
7. **Adult provisioning:** image-build path deliberately leaves adult initial account and password setup to the documented safe flashing workflow. Do not ship a factory default secret.

**Release classification:** `ENGINEERING PREVIEW / INSTALLABLE PAYLOAD`. Suitable for local demo and informed spare-media testing on a real Pi; **not hardware-certified, not a turnkey safe-for-children appliance, not a fully bootable image.**

## Physical Pi acceptance checklist

See `docs/PI4-INSTALLATION.md`, `docs/IMAGE-BUILD.md`, and `docs/SECURITY-AND-FAMILY.md`. An adult should first back up the current machine and use a spare SD card or SSD. After applying the installer, verify actual user separation, paths, world loading, app launching, network guard rollback, persistence after restart, and performance on the real Pi. Preserve the original boot media as the recovery path.
